# Google developer documentation style guide source map

Reviewed against the live English guide on 2026-08-18. This map covers the 69
current topic pages in the guide's navigation and the separate maintenance
history. It records the decision each page contributes; it does not reproduce
the source text.

Use this file to route an exact question to the authoritative page. Because the
guide changes, check [What's new](https://developers.google.com/style/whats-new)
and the live topic before relying on a detail that could have changed. The guide
itself places project-specific style first, the Google guide second, and its
listed third-party references after that.

     and permission to depart from the guide when readers benefit.
2. [Highlights](https://developers.google.com/style/highlights)

3. [Philosophy of this style guide](https://developers.google.com/style/philosophy)

## General principles

7. [Write accessible documentation](https://developers.google.com/style/accessibility)
   - Covers semantic structure, keyboard and screen-reader use, readable prose,
     links, media alternatives, tables, forms, interaction, and nonvisual cues.
8. [Avoid excessive claims](https://developers.google.com/style/excessive-claims)
   - Requires factual, scoped, verifiable performance, cost, security, and
     competitive statements instead of superlatives or guarantees.
9. [Future features](https://developers.google.com/style/future)
   - Prohibits unapproved pre-announcements and points durable documentation to
     present-tense, supported behavior.
10. [Write for a global audience](https://developers.google.com/style/translation)
    - Covers simple and unambiguous US English, translation-aware syntax,
      explicit helper words, consistent terminology, and cultural neutrality.
11. [Write inclusive documentation](https://developers.google.com/style/inclusive-documentation)
    - Covers gender-neutral, non-ableist, nonviolent, literal language; diverse
      examples; community-preferred identity terms; and unavoidable code terms.
12. [Jargon](https://developers.google.com/style/jargon)
    - Provides a decision test for removing, replacing, defining, linking, or
      minimally retaining specialized and overloaded terms.
13. [Prescriptive documentation](https://developers.google.com/style/prescriptive-documentation)
    - Favors a recommended path and distinguishes required, recommended,
      optional, possible, expected, and actual language.
14. [Third-party content](https://developers.google.com/style/other-sources)
    - Warns against copying public third-party text, images, code, logos, or
      speech; favors paraphrase and a link unless rights are known.
15. [Timeless documentation](https://developers.google.com/style/timeless-documentation)
    - Avoids date-relative words and assumed prior versions in durable product
      documentation while allowing explicit time context in dated content.
16. [Voice and tone](https://developers.google.com/style/tone)
    - Defines a conversational, friendly, respectful, concise voice that avoids
      slang, pushiness, jargon, cuteness, and unnecessary entertainment.

## Language and grammar

17. [Abbreviations](https://developers.google.com/style/abbreviations)
    - Covers audience-based expansion, first-use formatting, familiar forms,
      periods, prohibited shorthand, abbreviation verbs, and a/an by sound.
18. [Active voice](https://developers.google.com/style/voice)
    - Prefers explicit actors and active constructions while allowing passive
      voice when the object matters more or the actor is irrelevant.
19. [Anthropomorphism](https://developers.google.com/style/anthropomorphism)
    - Replaces human qualities attributed to software or hardware with literal
      technical actions.
20. [Articles (a, an, the)](https://developers.google.com/style/articles)
    - Requires articles for comprehension and translation, including in titles
      and headings.
21. [Capitalization](https://developers.google.com/style/capitalization)
    - Applies US English capitalization, official product casing, sentence
      case, lowercase after most colons, and nonvisual meaning distinctions.
22. [Contractions](https://developers.google.com/style/contractions)
    - Recommends common natural contractions, especially negative ones, and
      rejects invented or complex contractions.
23. [Pluralization](https://developers.google.com/style/pluralization)
    - Consolidates agreement, abbreviations, quantities, product and code
      names, optional plurals, and pronoun-related plural guidance.
24. [Possessives](https://developers.google.com/style/possessives)
    - Covers standard apostrophe forms and avoids possessives for products,
      trademarks, and bare code items.
25. [Prepositions](https://developers.google.com/style/prepositions)
    - Places prepositions where they read naturally, including sentence-final
      positions, while adding or removing them for clarity.
26. [Present tense](https://developers.google.com/style/tense)
    - Uses present tense for general behavior and future tense only for a
      genuinely later event, not a default product description.
27. [Pronouns](https://developers.google.com/style/pronouns)
    - Covers clear antecedents, demonstrative nouns, singular they, personal
      pronouns, and restrictive versus nonrestrictive relative clauses.
28. [Second person and first person](https://developers.google.com/style/person)
    - Addresses the reader as you, uses the imperative for instructions,
      distinguishes end users, and limits organizational we.
29. [Sentence structure](https://developers.google.com/style/sentence-structure)
    - Places circumstances, conditions, and goals before the dependent
      instruction.
30. [Verb forms in reference documentation](https://developers.google.com/style/reference-verbs)
    - Describes what a method does with present-tense third-person verbs rather
      than imperative verbs.

## Punctuation

31. [Colons](https://developers.google.com/style/colons)
    - Uses a colon after a complete introductory sentence and generally
      lowercases the following running text.
32. [Commas](https://developers.google.com/style/commas)
    - Covers serial commas, introductory phrases, clause boundaries,
      nonrestrictive which clauses, conjunctive adverbs, and because.
33. [Dashes](https://developers.google.com/style/dashes)
    - Uses unspaced em dashes for interruptions, rejects en dashes, and favors
      colons or periods for item-description pairs.
34. [Ellipses](https://developers.google.com/style/ellipses)
    - Avoids ellipses in ordinary technical prose and UI instructions while
      defining a narrow quotation-omission form.
35. [Hyphens](https://developers.google.com/style/hyphens)
    - Provides a clarity- and convention-based lookup strategy for prefixes,
      compound nouns, modifiers, ambiguity, and suspended hyphens.
36. [Parentheses](https://developers.google.com/style/parentheses)
    - Keeps parenthetical content short and nonessential and rejects optional
      plurals in parentheses.
37. [Periods and other end punctuation](https://developers.google.com/style/periods)
    - Covers sentences, lists, URLs, quotations, parentheses, headings,
      abbreviations, one-space separation, and restrained exclamation points.
38. [Quotation marks](https://developers.google.com/style/quotation-marks)
    - Uses straight double marks, defines punctuation placement and literal
      exceptions, and limits single marks to code or nested quotations.
39. [Semicolons](https://developers.google.com/style/semicolons)
    - Prefers simpler punctuation but permits semicolons for closely related
      clauses, conjunctive adverbs, and complex series.
40. [Slashes](https://developers.google.com/style/slashes)
    - Avoids slashes for alternatives, dates, abbreviations, and fractions but
      preserves them where code, paths, URLs, or established notation needs them.

## Formatting and organization

41. [Dates and times](https://developers.google.com/style/dates-times)
    - Covers written dates, ISO numeric dates, clock format, time zones, ranges,
      combined timestamps, abbreviations, and avoiding seasons.
42. [Format examples](https://developers.google.com/style/format-examples)
    - Chooses punctuation and placement for short, parenthetical, and extended
      examples introduced with such as, for example, or like.
43. [Diagrams, figures, and other images](https://developers.google.com/style/images)
    - Covers when to use visuals, file formats, screenshot privacy, alt text,
      introductions, captions, descriptions, embedded text, and video formats.
44. [Footnotes](https://developers.google.com/style/footnotes)
    - Prefers cross-references, notes, parentheticals, or normal prose; uses
      numbered superscripts only when a footnote is unavoidable.
45. [Headings and titles](https://developers.google.com/style/headings)
    - Covers sentence case, task versus concept phrasing, optional sections,
      abbreviations, code, unique H1s, hierarchy, and grouped sections.
46. [Use italics to discuss terms](https://developers.google.com/style/italics-terms)
    - Uses italics for a newly defined term on first mention and for a word or
      letter discussed as itself.
47. [Lists](https://developers.google.com/style/lists)
    - Chooses numbered, bulleted, and description lists; covers introductions,
      parallelism, nested steps, capitalization, punctuation, and run-in heads.
48. [Mathematical notation](https://developers.google.com/style/mathematical-notation)
    - Covers accessible symbols, spacing, variables, operators, equations,
      fractions, superscripts, subscripts, and complex-math rendering.
49. [Notes, cautions, warnings, and other notices](https://developers.google.com/style/notices)
    - Defines notice severity and limits notes to useful nonessential material,
      keeping required content in the normal flow.
50. [Numbers](https://developers.google.com/style/numbers)
    - Covers words versus numerals, ordinals, fractions, percentages, ranges,
      currency, separators, dimensions, exponents, and practical implications.
51. [Paragraph structure](https://developers.google.com/style/paragraph-structure)
    - Keeps one idea per paragraph, critical information first, short readable
      blocks, left alignment, and no forced in-paragraph line breaks.
52. [Format phone numbers in text](https://developers.google.com/style/phone-numbers)
    - Uses reserved example numbers, nonbreaking hyphens, explicit country
      codes for international forms, and the word extension.
53. [Procedures](https://developers.google.com/style/procedures)
    - Covers introductions, single steps, substeps, complex-step order,
      multiple paths, optional steps, action context, goals, results, and review.
54. [Tables](https://developers.google.com/style/tables)
    - Chooses tables for multi-dimensional data and covers introductions,
      captions, semantic headers, accessibility, placement, and anti-patterns.
55. [Units of measurement](https://developers.google.com/style/units-of-measure)
    - Covers numeral-unit spacing, abbreviations, pluralization, rates, ranges,
      decimal versus binary units, temperature, currency, and conversions.

## Linking

56. [Cross-references and linking](https://developers.google.com/style/cross-references)
    - Covers selective links, in-context help, descriptive text, introductions,
      unexpected behavior, tabs, external links, punctuation, and navigation.
57. [Make headings into link targets](https://developers.google.com/style/headings-targets)
    - Covers custom lowercase hyphenated anchors and preserving stable targets
      when headings change.

## Computer interfaces

58. [API reference code comments](https://developers.google.com/style/api-reference-comments)
    - Covers public API reference completeness, short first sentences, classes,
      members, methods, parameters, returns, exceptions, and deprecations.
59. [Code in text](https://developers.google.com/style/code-in-text)
    - Defines code-font and ordinary-text items, conditional cases, combined UI
      styling, HTTP status phrasing, and grammatical treatment of code.
60. [Code samples](https://developers.google.com/style/code-samples)
    - Covers project-specific indentation, line length, preformatted blocks,
      code omissions, introductions, and language code-style authorities.
61. [Document command-line syntax](https://developers.google.com/style/code-syntax)
    - Covers minimal runnable commands, prompts, wrapping, optional syntax,
      alternatives, repetition, output, and command-line terminology.
62. [Format placeholders](https://developers.google.com/style/placeholders)
    - Covers semantic and Markdown forms, uppercase underscore names,
      first-use explanations, multiple values, and placeholders in output.
63. [UI elements and interaction](https://developers.google.com/style/ui-elements)
    - Covers task-focused instructions, bold labels, UI terminology, menu paths,
      icons, fields, keyboard input, accessibility, and directional language.

## HTML and CSS

64. [HTML and semantic tagging](https://developers.google.com/style/semantic-tagging)
    - Uses elements for meaning, CSS for presentation, headings for hierarchy,
      and the correct semantic distinction among emphasis and styling elements.
65. [HTML formatting](https://developers.google.com/style/html-formatting)
    - Applies project HTML style, spaces and indentation, lowercase markup,
      trailing-space rules, line length, and code-wrap safety.
66. [Markdown versus HTML](https://developers.google.com/style/markdown)
    - Balances readable Markdown source with HTML's stronger semantic control
      and defers to the team's established source format.

## Names and naming

67. [Example domains and names](https://developers.google.com/style/examples)
    - Provides privacy-safe domains, email and person naming, company names,
      phone numbers, reserved IP ranges, addresses, projects, and service IDs.
68. [Filenames and file types](https://developers.google.com/style/filenames)
    - Covers lowercase hyphenated ASCII names, consistency exceptions, exact
      filename references, file interactions, and human-readable file types.
69. [Trademarks](https://developers.google.com/style/trademarks)
    - Defers to owner requirements and uses trademarks as unmodified modifiers,
      not standalone nouns, verbs, plurals, or possessives.

## Live lookup strategy

When the skill's synthesis and the source guide appear to differ:

1. Check the exact live topic linked in this map.
2. Check **What's new** for a recent change or consolidation.
3. Prefer the current page's body over an older summary, cached extract, or
   legacy page.
4. Preserve project-specific and official technical conventions when the guide
   treats its own guidance as a default.
5. Record a material exception or unresolved conflict instead of silently
   choosing whichever phrasing is easier.
